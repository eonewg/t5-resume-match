# 独立 AI 盲评 / LLM-as-a-Judge

用户已安排独立 AI 评审任务；A 准备材料和汇总程序，不代填评分，也不等待结果阻塞集成准备。当前为 **已收到 reviewer-ai.json 并完成汇总，待最终验收复核**，没有独立准确率、通过率或质量提升结论。结果属于 LLM-as-a-Judge，不是人工盲评或人工金标准。

打开 [离线盲评页](../../data/evaluation/2026-09-08/reviewer.html)，浏览器直接打开即可使用。共 21 项：3 份学生履历的解析核对、同一批 3×5 共 15 组岗位适配度、3 组原经历/模型改写比较。填写评审模型或任务代号、分数和原文依据后，点击“导出评分 JSON”，将文件交回。页面不联网、不调用模型；草稿保存在当前浏览器，最终以导出的文件为准。

评分期间不要打开 `operator-record.json`：其中保存算法预测、模型身份及 A/B 对照。盲评页不含这些信息；但改写文风仍可能透露来源，不能称为完全双盲实验。

## 固定输入与方法

- 使用 [独立材料](../../data/holdout/2026-09-08/README.md)的 3 份公开学生时期履历及 5 份 Canonical JD；不使用历史 40 组样本标签充当本次人工金标准。
- 解析草稿未经人工确认，P1–P3 专门记录漏项与误项。岗位判断先读完整原文，区分“缺失”“未证明”和“硬条件不符”，不将技能关键词出现视为精通。
- 匹配算法分数在评分阶段隐藏。15 组统一使用 keyword baseline，semantic off；本批不是 embedding 提升的因果实验。
- 改写评估选择每份履历**第一条解析经历（不截断该条目）**，没有截断段落；固定配对 J1、J4、J3。模型只接收该经历和对应完整 JD，不能把输出当成对整份简历的诊断。D1/D2 所选第一条解析经历实际仅含标题/时间，信息不足；保持已发评审的输入不变，不能宣称覆盖完整项目经历。3 次样本均保留，失败不另换材料补成功数。
- 两组请求完成但 star_rewrites 均为空（仅返回 JD 建议），第三组在既定重试后失败；失败在盲评页直接标明，不能当作正确空答案。请给实际可见结果评分，并在问题栏注明调用失败；汇总时失败率与成功结果的质量分别报告。
- `operator-record.json` 记录代码 SHA、固定输入 SHA-256、原输入、真实输出、调用耗时/可用 token 指标及失败类型；不含密钥、endpoint 或 thinking 内容。

## 评分与汇总

1–5 分越高越好。解析关注完整性与事实忠实；匹配关注岗位适配而非录用概率；改写关注清晰度、岗位相关性和事实保留，新增技能/职责/数字/成果应具体指出。每项必须填写理由；未评分保留空白，不填 0。

评分完成后运行：

```powershell
uv run --locked python -m scripts.summarize_ai_evaluation <导出的评分文件路径>
```

程序拒绝输入版本不一致、缺评审模型或任务代号、缺项或缺理由。输出包含 3 项解析均分、15 组 keyword 与评审模型判断的 Spearman 相关、非空改写的平均分差（当前没有非空改写，输出 null）及全部尝试/失败分母。相关系数不是准确率；单一评审模型、少量历史英文/中文样本不能外推市场。必须结合评审指出的事实问题逐条复核，不能由脚本自动批准合 main。

复现准备：`uv run --locked python -m scripts.prepare_final_evaluation` 仅重新渲染已有记录；`--live` 只执行仍为 pending 的固定样本，不自动覆盖失败。后续修复/新模型应另建独立版本，保留这次原记录。

返回文件处理：先原样保存为 `data/evaluation/2026-09-08/reviewer-ai.json`，记录 SHA-256，再校验和汇总到 `ai-summary.json`。已有不同原件时拒绝覆盖。原件已返回并原样保存，见 ai-summary.json；不生成或补填评分。21 项任务、输入 hash 和 A/B 映射保持原版本；2 成功、1 失败的真实调用记录不重跑、不替换。

评估补充核对：固定 D1/D2 的第一条解析经历只有标题/时间，真实响应虽成功但 `star_rewrites=[]`，只有 JD 建议。D3 是调用失败。三个原始记录和盲评输入不变；汇总分别报告请求完成 2、空改写 2、可评改写 0、失败 1，改写提升应为 null，不以空文本计算提升。早前另一次合成验收的 STAR 成功不替代本批结果。
