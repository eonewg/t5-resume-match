# 五页最终演示脚本

演示对象为 PR #8 合入后的 A。现场模型有延迟或失败风险，保留错误界面并说明；演示 fixture 只能标作演示数据。完整安装结果见 [fresh install](fresh-install.md)，固定质量评估见 [AI 报告](ai-evaluation-results.md)。

## 准备

按 README 安装并启动 PostgreSQL 版本；默认 Diagnosis 是演示服务，真实调用需要服务端配置。前端由同一个 FastAPI 服务提供，无额外 Node 构建或前端开发服务器。浏览器打开首页，默认进入“我的简历”。

市场演示先执行 `uv run --locked python -m scripts.import_final_samples --apply` 导入补充五份快照，再在“市场洞察”导入五份 Canonical。全新库仅导入这两批时应为十条、六家雇主、四条 USD 年薪、五条无区间、一条周期未知。

## 主流程（约十分钟，不含模型等待）

1. **我的简历**：粘贴原始履历，点“整理简历内容”。先展示原文，再核对姓名、教育、技能和经历。不得把解析草稿当已核实事实。
2. 修改或清空一个字段，重新整理，说明已修改字段受到保护；展开“发现新的建议”，仅在事实正确时主动采用。
3. 勾选核对后“确认并保存”，等“已保存并重新读取”。刷新页面，在已保存版本中选择并载入，确认原文及编辑字段保持。
4. 点“选择目标岗位”，展开“添加目标岗位”；填写名称、公司和完整要求，点“整理并保存岗位”。也可选择已有真实快照，查看完整原文和来源。
5. 点“分析与我的匹配度”，进入**匹配分析**。展示后端真实分数、已匹配能力和待补能力；展开“查看匹配依据”。分数是关键词覆盖/可选增强，不是录用概率。
6. 点“优化这份简历”，进入**简历优化**。确认姓名和岗位正确，再生成建议。真实调用只显示真实结果；等待时按钮不可重复提交。
7. 对照“原文”和“建议表达”，解释 STAR 组织、岗位重点及待补信息。复制仅复制文字；返回简历核对修改并另存版本，不自动采纳未经核实的事实。
8. 失败时展示真实错误和“重试生成建议”；不保留旧成功结果冒充本次成功。不为演示关闭校验或切换演示服务掩盖失败。
9. **市场洞察**：说明来源、日期、样本量和雇主数，展示技能分布并展开词云。查看薪资分组及来源明细，说明未知值不填零、币种周期不混算。
10. 切到 390px，依次使用五个底部导航；展示保存版本可重新载入、来源宽表可在表内滚动。最后给出真实测试记录及已知限制。

## 可控回归材料

自动化使用明确合成输入：原文含 Python/SQL，确认字段仅保留 SQL 和“使用 SQL 汇总 120 条课程记录，整理了结果。”；岗位要求含 SQL、Python、数据分析说明，关键词分数 33.33%。这是验证确认值与旧原文隔离的样例，不是真实学生成果。真实采样与合成输入的市场统计分开。

付费链路：`T5_RUN_LIVE_BROWSER=1` 后运行 `node tests/core/final-live-smoke.cjs`。普通 UI 回归：`node frontend/tests/ui-smoke.cjs`，诊断丰富内容明确使用演示 fixture。两者需要单独安装 Playwright 和可用 Edge，并按脚本说明准备数据库；它们不属于应用运行依赖。
