## 已知限制

- 默认 Diagnosis 为显式 Mock；真实模型需服务端配置。三协议通过离线适配测试，不表示三个厂商都已真实联网验收。本次真实模型为 custom/openai_chat/glm-5.2。
- 规则解析依赖格式与词表；关键词覆盖不衡量精通程度、硬条件、录用概率。模型事实保护能阻止部分原文/数字异常，不能证明所有语义事实正确，改写必须核对。
- 真实评估两组成功耗时 27.253、23.577 秒，第三组 93.146 秒后失败（含既定重试）。保留失败分母，不能只计算成功案例质量后宣称稳定。
- 单一评审 AI、小样本和文风线索可能引入偏差；评分不能称作人工金标准、完全双盲或整体准确率。结果已返回，见 [评分汇总](ai-evaluation-results.md)。
- 真实 JD 样本混合资历、地区、语言及采集形式；不能推断应届生平均薪资或整个就业市场。四条年薪仅展示原区间，不加入股权福利；Scale 周期未知不猜测。
- 本地单用户应用，未实现多用户隔离和生产部署；SQLite 仅用于便捷演示。最终环境安装复现尚未在 UI 最终版本执行。
- 两款竞品的登录后核心体验受工具阻塞，见 [体验记录](../competitor-analysis.md)。不能据此推断其功能缺失。

## 演示顺序（最终 UI 后复核）

1. 展示模块真实/Mock 状态与来源说明。
2. 粘贴选定履历，保留原文并解析草稿。
3. 核对教育、技能、经历，演示手动修正与清空保护。
4. 保存后重新读取该版本。
5. 输入或选择真实 JD，检查技能和来源。
6. 运行 keyword 匹配，解释分数、matched/missing 与硬条件限制。
7. 调用真实 Diagnosis，展示原经历与 STAR 对比。
8. 展示 JD 定向建议、待补量化信息和事实核对；错误时保留真实失败状态。
9. 导入两批市场样本，展示词云、薪资、技能分布及缺失项。
10. 展示评估/测试证据与已知限制，最终 UI 集成后复核移动端与完整流程。
