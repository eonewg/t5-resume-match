# Vitae 本机 AI 设置

设置以模型配置列表为主，每行展示名称、模型和 API 地址，右侧提供功能勾选、编辑与删除。

## 使用

岗位与截图导入：在配置列表勾选「岗位与截图识别」，可分配现有支持图片输入的 DeepSeek `deepseek-flash` 或其他兼容模型；独立于三个文本功能，支持 Chat Completions 与 Responses。未分配时使用启动时简历模型配置快照，模型需支持图片输入。「测试连接」仍只测试短文本，不能证明图片能力。

简历和岗位页面均有独立「从截图导入」卡片，支持 PNG/JPEG/WEBP，最多 10 MB、2500 万像素。选择或拖入图片只显示本地预览，可更换或移除；点击「识别截图」才发送至配置的模型。图片不持久化，也不自动创建简历或岗位；识别后必须核对并保存。简历的「上传文档」仅接受 PDF/DOCX/TXT，沿用已编辑字段保护流程。岗位可编辑地点、薪资、学历、经验、技能/工具、职责目标、任职要求与加分项；拆分字段中的序号各自从 1 连续排列，转录原文保留原序号。拆分字段作为后续匹配与诊断输入，原文另存备查。OCR 可能漏字，原文不等于逐字正确的保证。

岗位公共契约新增可选字段 `location`、`education_requirement`、`experience_requirement`、`responsibilities`、`requirements`、`preferred_qualifications` 和 `original_text`；旧纯文本请求继续有效。识别失败、内容拒绝和截断均返回失败，不自动重试或用 Mock 代替。截图不提供可核实链接时来源保持 `unknown`。

侧栏「设置」支持创建多份命名配置。新建时默认选择 DeepSeek，预填 https://api.deepseek.com、deepseek-flash 和 Chat Completions，也可选择其他服务商。填写自己的 API Key，测试连接后点击「保存配置」。在列表右侧勾选简历识别、匹配分析或 AI 优化即可应用；每个功能仅使用一份配置，勾选另一行会直接切换，取消勾选恢复默认。列表下方显示各功能当前配置。

简历识别、匹配分析、AI 优化分别记录所选配置。已有配置可重命名、编辑；修改正在使用的配置会同步更新使用它的功能，未使用它的功能保持原选择。正在使用的配置须先切换或恢复启动配置，再删除。「恢复启动配置」仅解除功能的自定义选择，保留供应商列表。支持 Chat Completions；简历识别与 AI 优化也支持 Responses，匹配综合评估仍使用 Chat Completions。模型需满足原有结构化 JSON 输出要求。

API Key 默认隐藏；点击「显示」可查看已保存密钥，再次点击隐藏。密钥不会进入 localStorage、岗位/简历数据库、常规读取响应或日志。根据用户选择，保留本机配置供下次启动；关闭设置后丢弃页面草稿和已显示密钥，服务退出时释放本次运行配置引用。

配置以 UTF-8 保存于运行目录 `.runtime/ai-settings.json`，密钥随配置保存在该本机文件中；文件被 Git 忽略，便携包白名单不包含它。写入临时文件、刷新落盘后原子替换；应用只在保存成功后切换 provider，进行中的请求继续使用原实例。配置优先于启动时的模块配置，恢复操作回到启动快照，不改写 `.env`。旧版单配置文件读取时转换为命名配置。

「测试连接」仅在点击时发起一条短测试消息，不发送简历/JD，不自动保存或切换。完整响应、鉴权和接口形式可以通过连接测试，业务结构化输出和事实保护仍由原模块校验。不能把连接成功视为简历/诊断质量验收。

侧栏「保存并退出」持久化现有配置后请求 Uvicorn 正常退出；设置内同名按钮同样保留已保存配置后退出，编辑期间不可退出，需先保存或取消编辑。保存失败或版本冲突不会关闭服务。保留已保存的数据库记录和本机配置；浏览器页面显示退出状态，服务进程结束。这里的保存指 AI 配置，不替代简历页面的核对保存。再次运行 `start.ps1` 或便携程序即可恢复。帮助入口改为「使用帮助」，内容为操作说明。

## 接口

全部接口位于 `/api/v1/settings/ai`，仅允许本机地址和同源访问；响应不缓存。默认测试实例不读取本机持久化文件，也不允许停止进程；需要测试时显式指定临时配置路径和退出回调。

- `GET /`（无尾斜杠）：返回 revision、profiles、modules、warning、can_exit；不包含密钥值。
- `PUT /`：接收 profile_id（新建时为空）、profile_name、base_url、model、api_style、api_key、modules、revision。modules 为空只保存；非空同时应用。空密钥表示保留同地址已有密钥；改地址必须重新填写。返回 saved_profile_id。
- `POST /activate`：profile_id、modules、revision，切换所选功能。
- `POST /profiles/delete`：profile_id、revision；使用中的配置返回 409。
- `POST /reset`：modules、revision，解除自定义选择。
- `POST /key`：module、可选 profile_id、revision，显式返回本机密钥，Cache-Control 为 no-store。
- `POST /test`：与配置写入相同字段，仅接受一个 module；不持久化。
- `POST /save-exit`：revision、可选 update（完整配置写入参数）；保存成功后发送退出响应，再触发服务正常停止。

revision 防止多个设置窗口相互覆盖。校验或写盘失败不会改变当前 provider。无效持久化文件保留并在界面报告，启动配置作为明确提示的临时运行配置。

岗位创建在 `#/jobs/new`，岗位库在 `#/jobs`，通过岗位工作区内的页签切换。创建页支持粘贴原文、上传 PDF/DOCX/TXT、截图识别和手动填写。文档先提取文字，用户点击「用 AI 识别岗位」才调用上述模型；文本识别不要求图片能力。识别后保留手动修改过的字段（包括清空），可逐项采用候选内容。草稿在当前页面会话内跨路由保留；保存成功并重新读取后才选中，读取失败重试不重复创建。

简历库入口也位于简历工作区内，侧栏不单列资料库。匹配与优化页可搜索已保存简历和岗位，支持姓名、教育、版本、公司及技能关键词；输入仅过滤，选择条目才切换，分析仍需主动点击。
