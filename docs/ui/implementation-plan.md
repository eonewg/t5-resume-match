# UI 产品化方案与功能边界

基线 41ab5ce；分支 feat/ui-refresh-d。仅修改 frontend 与 UI 文档。

## 已审阅现有实现

原生 ES modules + CSS，通过 mount(container, context) 接公共壳；不是 React/Vite 工程。本次不新增框架、根依赖或后端接口。
Resume 保留解析候选、字段确认、版本历史、保存后重读、离开页草稿及迟到响应保护。
Jobs 使用真实 /jobs、/resumes、/matches；单独 matching 导航复用这些接口，匹配结果保留在当前 workspace，选择变化时失效。
Diagnosis 使用 /diagnoses，summary/suggestions 是现有公共字段；已知 STAR 文本可拆原文/建议，未知格式原样安全显示，不发明富 schema。
Analytics 保留来源/日期过滤、归档导入、技能频率/词云、分币种周期薪资区间、缺失值和来源明细。

## 页面与交互

1. 我的简历：默认落点；原文整理与确认内容明确区分；移动端原文可折叠，保存与下一步仍可达。
2. 目标岗位：已保存岗位选择与详情优先，新增表单折叠；进入匹配分析前保留当前选择。
3. 匹配分析：独立导航，真实结果和关键词事实列表为主；完整计算说明折叠，缺失能力不等于不会；重新计算显式触发。
4. 简历优化：概览、岗位建议、经历对照、核实提醒；复制建议后返回编辑，不提供无公共 API 支撑的自动采用。
5. 市场洞察：可读条形图优先，保留词云和表格；未知薪资显示暂未提供。

快捷原文流程作为次级入口保留，不再是默认首页。演示标记用“演示数据”，服务失败不显示成功建议。

## 首版 critique（待后续变体补充）

Stitch 我的简历首版保留双栏和新建议，但自动添加了用户头像、通知与英文品牌，以及常驻状态示例；这些没有产品功能依据，必须在变体及实现中去除。采用简洁版本选择器，不虚构版本日期。
当前移动端原文输入占据过长首屏；新方案使用较短输入区与折叠原文，不改变内容。
目标岗位首版列表/详情与折叠表单方向可用；长岗位名称及无薪资状态需真实浏览器核验。

## 验证计划

保留原有 controller 测试；新增真实 UI 主流程、移动导航、字段保护/重读、选择失效、匹配→诊断、服务失败恢复与术语检查。浏览器测试使用公共本地服务和隔离测试数据库；模型结果使用明确演示替身，不因 UI 工作额外调用收费 API。

匹配首版 critique：Stitch 说明自动加入教育/经历分项评分，公共接口没有此类评分维度；变体必须删除。实现仅展示后端 score 与原样 gap_analysis，不能从设计图反推业务算法。
